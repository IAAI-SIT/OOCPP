# 第10章 运算符重载综合复习项目：Fraction

## 项目定位

用一个 `Fraction`（分数）类把第10章 10.1～10.7 的核心内容串起来。

课堂主线：

**先预测 → 再写/补全 operator → 编译运行 → 边界测试 → AI审查 → 人工验证**

## Solution 中的版本

| 项目 | 复习重点 |
|---|---|
| V0_Baseline | 不使用运算符重载时，普通成员函数为什么表达不自然 |
| V1_BinaryOperators | 双目运算符 `+`、`-`；成员函数形式；不应偷偷修改操作数 |
| V2_CompareOperators | `==`、`!=`；先定义“相等”的语义；复用已有运算 |
| V3_MemberVsNonMember | 成员函数与非成员/友元函数；`f + 2` 与 `2 + f` |
| V4_IncrementOperators | 前置 `++` 与后置 `++(int)`；对象状态和表达式结果 |
| V5_StreamOperators | `<<`、`>>`；为什么参数和返回值都使用流的引用 |
| V6_Integrated | 全部内容合并，并用一组测试统一验证 |

## 建议课堂节奏（约45分钟）

1. 5分钟：V0，提出“为什么对象不能自然地写 +、==、++、<<？”
2. 8分钟：V1～V2，双目和比较运算
3. 7分钟：V3，成员函数 vs 非成员/友元函数
4. 8分钟：V4，前置/后置 ++
5. 7分钟：V5，<< / >>
6. 7分钟：V6，综合测试
7. 3分钟：AI审查 + 人工验证结论

## 课堂重点

- 运算符重载本质上仍然是函数。
- 不改变运算符的操作数个数、优先级和结合性。
- 成员函数中左操作数是 `*this`。
- 非成员/友元函数的两个操作数都显式传入。
- `+` 应保持“产生新值”的通常语义，不应偷偷修改左操作数。
- 后置 `++` 的 `int` 是用于区分前置/后置的占位参数。
- `operator<<` / `operator>>` 返回流引用，才能连续使用。
- AI给出的代码必须编译、运行并用边界测试验证。
